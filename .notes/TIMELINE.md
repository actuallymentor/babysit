# Timeline

- **2026-08-01 (Claude/Codex model default audit)**: Codex moved to `gpt-5.6-sol` with `model_reasoning_effort="xhigh"`, replacing GPT-5.5 after OpenAI's live resolver and model guide named GPT-5.6 Sol as the frontier model. The Codex first-run NUX suppression list now includes both `gpt-5.6` and `gpt-5.6-sol`.
- **2026-08-04 (named active sessions)**: Added optional human-readable session names, exact active-name reopening, and a `NAME` column in session listings. Names remain metadata-only and survive resume; all-digit names are reserved for numeric selectors.
- **2026-08-04 (persistent resume inventory)**: Added a zero-argument `babysit resume` history table backed by the durable Babysit session registry. It shows canonical Babysit IDs beside captured native agent IDs and sorts launches newest first. Native-id lookup now resolves repeated conversations to the latest Babysit launch. Host-native Codex/Claude histories remain excluded because their transcript stores are not mounted into Babysit's persistent agent-state volumes. Post-review hardened the dependency-check exemption to agent-less listings and made null legacy timestamps display as unknown. Released as v0.24.0.
- **2026-08-06 (active-session table readability)**: Reordered `babysit list` and numbered `babysit open` tables to show name, status, agent, ID, and tmux session in that order. Column widths now derive from visible values so long names and IDs remain aligned, while long tmux session names sit harmlessly in the final column. Released as v0.24.1.
- **2026-08-06 (global active-session numbers)**: Numbered every row in `babysit list` and made `babysit open N` resolve that global row from any directory. Bare `babysit open` still filters by the current workspace, but its multi-match table preserves the global list numbers so displayed selectors never change meaning. Released as v0.25.0.
- **2026-08-06 (release pipeline hardening)**: Added a pre-release unit-test gate, pinned Bun 1.3.13 with frozen lockfile installs and the correct cache key, and made the binary release invoke the reusable Docker workflow so versioned binaries and images deploy together. Releases are serialized with GitHub's extended pending queue, release tags point at the exact tested commit, semantic-version ordering determines the latest release, and versioned Docker tags use isolated concurrency. Nightly/asset builds update only `latest`, so rolling builds cannot displace a pending release deployment. GitHub Actions use their Node 24-compatible majors.
- **2026-08-06 (Watchtower compatibility guard)**: Researched maintained forks, popular rebuilds, registry aliases, and legacy Watchtower images. Babysit now recognizes exact repositories confirmed safe for its stateful agent containers, scans running Docker containers before launch, and emits a high-visibility warning for unknown or legacy Watchtower-like names that may ignore the exclusion label.
- **2026-08-07 (v0.26.1 release)**: Released the Watchtower registry-alias fix through the package-triggered GitHub Actions workflow. The Build & Release run completed successfully.
- **2026-08-07 (housekeeping audit)**: Revalidated agent defaults, CLI flags, pinned container tools, workflow actions, generated configuration safety, documentation, and test isolation. Claude moved to `xhigh`, Gemini to `--approval-mode=yolo`, OpenCode to `openai/gpt-5.6-sol`, sample supervision rules became opt-in, and resume tests stopped touching the user's session registry.
- **2026-08-07 (host agent profile isolation)**: Added `--ignore-host-agents-md` as a persistent session modifier. It removes shared/native global instruction and skill mounts, executable `~/.babysitrc`, GitHub configuration, Gemini UI/tracking state, and other copied Claude/Codex/Gemini preferences while retaining dedicated credentials and minimal login/first-run state. Both resume forms remain isolated, the host `~/.agents/LOOP.md` fallback is disabled in foreground and detached monitors, and project-local workspace instructions remain available. GitHub host/account tokens are sanitized into a credential-only profile carried through a short-lived private Docker env file, so Enterprise and nested-Docker authentication work without leaving host token files behind.
