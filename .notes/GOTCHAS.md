# Gotchas

Keep only pitfalls that remain relevant to the current implementation. Numbers are stable references, so removed entries leave intentional gaps.

1. **Two-phase Claude Keychain OAuth** — detect credential existence *before* the Claude `--version` pre-flight. Claude can rotate its token during that check, so capture the Keychain value *after* pre-flight. Codex, Gemini, and OpenCode do not rotate tokens on `--version`; see gotcha 41.
2. **Docker inode tracking** — never `mv` a bind-mounted credential file. Docker tracks the original inode. Use `writeFileSync` (in-place) instead.
3. **ANSI cursor-forward** — `\x1b[nC` is used as visual whitespace by TUI agents. Replace with real space *before* stripping ANSI, or pattern matching breaks.
4. **Tmux session name limit** — ~256 chars max. Hash long paths (>200 chars) using SHA-256 truncated to 16 chars.
5. **Debounce auto-accept** — 3s minimum between consecutive auto-accepts. TUI redraw flicker causes false double-fire.
6. **Sync daemon cleanup** — use `unref()` on detached children, not `disown`. Avoids "Terminated" message on stderr.
7. **node_modules isolation** — Linux container produces Linux-native binaries. Mount a docker volume over `/workspace/node_modules` instead of bind-mount to prevent host breakage.
8. **Claude plan acceptance is a numbered choice** — current Claude Code presents plan actions as numbered options that are submitted with Enter. Shift+Tab is still useful for explicit TUI feedback/mode controls, but it is not a semantic `accept` action. Keep Babysit's `accept` alias mapped to Enter and reserve `shift_tab` for callers that genuinely need back-tab.
9. **mri's `unknown` callback halts parsing** — when set, mri returns the callback's return value instead of the parsed result. Don't use it for "include unknown args" — omit `unknown` entirely and identify known flags after parsing.
10. **tmux `send-keys -l` consumes all remaining args** — `Enter` after a `-l text` arg gets sent as literal text, not a key press. Send the literal text and the Enter in two separate `send-keys` calls.
11. **tmux `send-keys` shift+tab** — pass the named key `BTab`, not the literal escape string `\x1b[Z`. tmux interprets unrecognised key names as text input.
12. **Don't bind-mount the host's `~/.claude/settings.json`** — Claude rewrites it at runtime and would overwrite the user's host settings. Build a tmpfile that merges host settings + babysit overrides and mount that instead.
13. **`build_docker_command` returns a string consumed by `sh -c`** — every value-bearing arg (env values, passthrough args, paths with spaces) MUST be shell-quoted. We use a single-quote wrap with `'\''` escaping for embedded quotes. Tests in `tests/docker.test.js` guard this; do not regress to a plain `flags.join(' ')`.
14. **Codex `resume` is interactive, `exec resume` is non-interactive** — babysit supervises through tmux, so the codex adapter must use `[ 'resume', id ]`. The `exec resume` form would launch in a non-interactive mode that can't be supervised.
15. **Docker image namespace is `actuallymentor/babysit`, not `babysit/babysit`** — both the publish workflow and the runtime pull/run must agree. Source in `src/docker/update.js` was originally wrong; tests in `tests/docker.test.js` lock this in.
17. **mri normalises `--no-X` to `{X:false}`, not `{'no-X':true}`** — listing `'no-update'` in `boolean:` makes mri quietly drop the flag and store `update:false` instead. Detect with `args.update === false`. Symptom: `--no-update` was silently ignored, self-update always ran.
18. **Bun-compiled binaries can't `readFileSync` source-tree assets** — `__dirname` resolves to `/$bunfs` at runtime, so `readFileSync(join(__dirname, '../foo'))` errors with ENOENT for both `package.json` and our `system_prompt/*.md`. Use import attributes instead: `import x from './x.json' with { type: 'json' }` for JSON, or move text content into a `.js` module and import it normally. (Bun supports `with { type: 'text' }` but Node 24 does not, so the JS-module pattern is the cross-runtime safe choice.)
19. **Codex global instructions live at `${CODEX_HOME}/AGENTS.md`, NOT `instructions.md`** — older codex versions read `~/.codex/instructions.md`, but current docs only honor `AGENTS.override.md` then `AGENTS.md` at the global scope. Writing to `instructions.md` silently does nothing. Babysit was bitten by this between v0.3.0 and v0.3.2 — codex was launching without any of the babysit system prompt.
20. **Gemini's `GEMINI_CLI_HOME` is a parent dir, not the config dir** — gemini creates `.gemini/` *inside* whatever `GEMINI_CLI_HOME` points to. Setting it to `/home/node/.gemini` (the actual config dir) would have gemini look at `/home/node/.gemini/.gemini/` for everything. Set it to the parent (`/home/node`) instead. Codex / claude / opencode use the opposite convention — their env vars point at the config dir directly.
21. **Each agent's credentials live in a different shape** — `keychain_service`-only logic in `credentials/darwin.js` will silently drop adapters that declare just a `file:` field (opencode does this). Always handle keychain → fallback_file → standalone file → env_key as four independent paths, and let env_key stack additively on top of file-based creds.
22. **OAuth file paths per agent** — claude: `~/.claude/.credentials.json` (linux) or Keychain `Claude Code-credentials` (darwin, with file fallback). codex: `~/.codex/auth.json`. gemini: `~/.gemini/oauth_creds.json`. opencode: `~/.local/share/opencode/auth.json` (no Keychain on any platform — opencode doesn't use it).
24. **Pre-create every credential dir in the Dockerfile** — when `docker run -v /tmp/foo:/home/node/.codex/auth.json` lands and `/home/node/.codex` doesn't exist in the image, docker auto-creates the parent as root, which blocks the `node` user from writing refreshed tokens or babysit-generated prompt files into it. Add the dir to the `mkdir -p` list in `Dockerfile` *before* the `chown -R node:node /home/node` line.
25. **Claude `--sandbox` cannot bind-mount writable session dirs** — `~/.claude/{projects,plans,todos}` is where claude writes per-session JSON. Mounting host paths read-only crashes claude on first write; bind-mounting read-write would touch host state in a mode that's supposed to be ephemeral. Skip the mounts entirely in sandbox so claude writes inside the container.
26. **The supervisor must outlive the foreground cli** — the user expects `babysit <agent>` to drop them into the agent's tmux session, then detach with Ctrl+B d and have the supervisor + container keep running. If the monitor loop runs in the foreground process, it dies the moment the user detaches and the agent goes unsupervised (and credentials stop refreshing). Pattern: spawn `babysit __monitor <id>` as a detached child (`{ detached: true, stdio: 'ignore' }` + `unref()`), then `execSync` `tmux attach` in the foreground. The detached daemon re-loads session metadata from `~/.babysit/sessions/<id>.json` to reconstruct config/agent/patterns/cwd.
27. **`config.commands` execSync freezes the supervisor** — running babysit-yaml-defined shell commands via `execSync` blocks Node's event loop, which means pane capture and rule evaluation freeze for as long as the command runs. A user-supplied notify_command that does a slow curl can pause supervision for seconds. Use `spawn` (with `stdio: 'inherit'`) and await its `close` event instead.
28. **bun-compiled binary detection via `process.argv[1]`** — node sets it to the script path (e.g. `src/index.js`); bun-compiled binaries set it to a synthetic `/$bunfs/root/<basename>` path. Check `argv[1]?.startsWith('/$bunfs')` to detect the compiled mode when re-spawning self. `process.execPath` reliably points at the right binary in either case.
29. **Staged tmpfile perms — `writeFileSync(path, content, { mode: 0o666 })` is masked by umask** to 0o664 or 0o644. Agent config and credential tmpfiles are uploaded with `docker cp`; the entrypoint remaps ownership under `/home/node`, but the client-side sync copy must also stay writable for later pulls. Always follow the write with `chmodSync(path, 0o666)` through the shared tmpfile helpers. Private one-shot bootstraps are the exception: keep their directory/file at 0700/0600 and let the root entrypoint consume them.
30. **Claude `.claude.json` carries onboarding/trust state** — without `hasCompletedOnboarding: true`, a `projects[/workspace].hasTrustDialogAccepted: true` entry, AND a high `lastOnboardingVersion`, claude treats every fresh container as a brand-new install (or as "version-upgraded since onboarding"), pops the theme picker AND the workspace-trust dialog. Neither has a CLI flag override. Babysit copies or synthesizes this state, sets all three flags (using the `9999.0.0` sentinel), and stages it into `${CLAUDE_CONFIG_DIR}/.claude.json` before container start. Isolation must build it from an empty host preference base.
31. **Claude `~/.claude/{projects,plans,todos}` should be named docker volumes, NOT bind mounts** — bind-mounting hits two failure modes back-to-back. (a) The host dirs typically have 0770 owner perms, which the container's `node` user can't write, so claude renders an EACCES error mid-chat. (b) If the agent works around (a) by `sudo chown -R node:node /home/node/.claude/plans`, the chown propagates back to the host bind mount and silently changes ownership of the user's host dirs — wrecking subsequent host-side claude runs. Named volumes (`babysit-claude-{projects,plans,todos}:/home/node/.claude/...`) sidestep both: claude has full write access, host dirs aren't touched, `babysit resume` still finds the session because the volume persists across container restarts.
32. **Codex trust + model nags persist per-install** — the trust dialog ("Do you trust the contents of this directory?") is bypassed by adding `[projects."/workspace"]\ntrust_level = "trusted"` to the mounted `~/.codex/config.toml`. The "Try new model" intro for each gpt-5.x release is bypassed by adding entries under `[tui.model_availability_nux]` (e.g. `"gpt-5.4" = 2`). Both nags would otherwise stall the supervised session on every fresh container. Babysit's `codex_extra_mounts` injects both. The `CODEX_KNOWN_MODELS_FOR_NUX` list needs maintenance as new gpt versions ship.
33. **Codex `installation_id` mount triggers "Failed to create session: Operation not permitted"** — empirically, mounting `~/.codex/installation_id` from the host into the container makes codex's session-tree machinery fail with EPERM on `/home/node/.codex/sessions`. Cause unclear (likely io_uring + seccomp, or a per-install file-locking scheme), but the fix is to NOT mount installation_id and let codex generate a fresh one per container. There's a regression test in `tests/setup.test.js` that asserts `codex_extra_mounts()` excludes installation_id.
34. **Gemini "logged in" state spans multiple files** — `~/.gemini/oauth_creds.json` alone is not enough. Without `~/.gemini/settings.json` carrying `security.auth.selectedType`, Gemini drops into its auth picker. Stage settings/account/trust files before start. In isolation, whitelist only `selectedType`; `enforcedType` and `useExternal` are host policy/flow preferences, not credentials, and can force reauthentication. Keep `google_accounts.json`, but omit `installation_id` and `state.json`.
35. **Gemini CLI no longer serves individual Google-login accounts** — individual-account support ended on 2026-06-18 and moved to Antigravity. Babysit can still adapt Gemini CLI for enterprise Code Assist and API-key users, but it must not claim that an unpinned model restores individual-account compatibility.
36. **OpenCode model names follow a live provider catalog** — the old built-in `gpt-5.5-pro` was rejected by ChatGPT-account auth. Babysit currently pins `openai/gpt-5.6-sol`, which appears in OpenCode's OpenAI catalog; revalidate this default whenever the catalog or account support changes. Users with non-OpenAI providers override it via `--model provider/model`.
37. **Codex `apps` feature triggers a noisy `codex_apps` MCP token-expired warning on every startup.** The `apps` feature (default-on, stable per `codex features list`) spawns the codex_apps MCP, which connects to OpenAI's hosted Drive/Slides/etc connectors and demands a fresh OAuth access token at startup. Babysit's pre-flight refresh (`<agent> --version`) does NOT actually refresh the codex token — confirmed empirically: `auth.json` mtime is unchanged after `codex --version`, `codex login status`, `codex mcp list`, and similar non-session commands. So any container started >1h after the user's last interactive codex run reliably hits `MCP client for codex_apps failed to start: ... token_expired`. Connectors are useless inside a sandboxed coding-agent context anyway, so we disable the feature in babysit's mounted `config.toml` via `[features]\napps = false` (equivalent to passing `--disable apps`). See `inject_codex_first_run_bypass` in `src/agents/setup.js`. To re-enable for a specific session: `babysit codex -- -c features.apps=true` (passthrough).
38. **Codex warns and falls back to a vendored bubblewrap when the system one is missing.** The base node:24-slim image doesn't include bubblewrap, so codex prints `⚠ Codex could not find bubblewrap on PATH` on every container startup before falling back. Add `bubblewrap` to the apt-get list in `src/docker/assets/Dockerfile` to silence it. The vendored fallback works fine, but the warning looked alarming enough that users asked about it.
39. **Install/update target is `~/.local/bin/babysit`, not `/usr/local/bin/babysit`.** The original install.sh used `/usr/local/bin` (root-owned, sudo-required), which meant `babysit update` had to escalate via `sudo mv` on every binary swap. Switched both `scripts/install.sh` and `src/cli/update.js` to write to `~/.local/bin` so the entire install/update lifecycle is sudo-free. Migration handling: when `process.execPath` lives in a non-user-writable dir (legacy install), `babysit update` writes the new binary to `~/.local/bin` and prints a one-time notice telling the user to `sudo rm` the legacy copy themselves — we never escalate automatically. PATH ordering matters: `~/.local/bin` must come before `/usr/local/bin` or the legacy binary keeps shadowing the new one. Keep the constant in update.js (`USER_INSTALL_DIR`) in sync with install.sh's `INSTALL_DIR`.
40. **`skipDangerousModePermissionPrompt` is top-level in claude's settings.json, NOT nested under `permissions`.** Claude only honours the field at the root. Putting it under `permissions: { skipDangerousModePermissionPrompt: true }` looks plausible (it's adjacent to `defaultMode`, `allow`, `deny`, etc.) but silently does nothing — the warning dialog still fires. Babysit injects this into the merged settings tmpfile when `mode.yolo` is on; see `build_claude_settings_tmpfile` in `src/agents/setup.js`. The field is also ignored when set in project settings (`.claude/settings.json`); it must be in user-scope settings, which is what babysit's tmpfile mount provides via `/home/node/.claude/settings.json`.
41. **Pre-flight `<agent> --version` does NOT rotate codex/gemini/opencode tokens.** Claude refreshes on `--version`, but codex/gemini/opencode only refresh on real API calls — empirically confirmed: `auth.json` mtime is unchanged after `<agent> --version`. So pre-flight is a silent no-op for those three. The host's auth.json keeps the original refresh_token, babysit copies it, the container refreshes (rotating one-time-use refresh_token X → Y), writes Y to the bind-mounted tmpfile but NOT back to the host file. Next babysit session reads the now-server-invalidated X from host → first refresh attempt fails with `"Your access token could not be refreshed because your refresh token was already used."` Fix: bidirectional credential sync — `start_credential_sync` takes a `write_destination` callback and pushes container-side updates back to the host file on every tick + on `stop()`. Conflict policy is source-wins (host re-auth beats container refresh). Keychain-backed creds (claude on darwin) intentionally stay one-way because claude's pre-flight rotation works reliably and writing back to Keychain has a different shape than a file write. Recovery for users hitting this on an already-invalidated host file: re-auth on the host (`codex auth login` etc.).
42. **Value-flag normalization must feed passthrough collection too.** For `--log`, parse.js rewrites a bare flag to `--log=` before giving argv to mri so `--log --yolo` does not consume `--yolo` as a value. `collect_passthrough` must use that same prepared argv. If it uses the original argv, it will still treat bare `--log` as a value-taking flag and drop the next passthrough token; e.g. `babysit claude --log --model sonnet` becomes just `sonnet` for the agent.
43. **Do not type the docker boot command into tmux when setting up early `pipe-pane` logging.** `send-keys -l "exec ${command}"` would capture startup output, but it also echoes the full docker command into the pane/log, including env values. Start the pane with a shell that waits on `read`, pass the command as a shell argument, attach `pipe-pane`, then send a blank Enter so no command text is echoed before execution.
44. **The monitor daemon must reuse every foreground credential tmpfile.** `copy_host_file_to_tmpfile` produces a new path on each call, so a monitor-created copy would never observe the container's OAuth refreshes. Foreground launches store per-agent `creds_tmpfiles`; `cmd_monitor` passes them back as `existing_tmpfiles`. The singular fields remain only as compatibility fallbacks for older session records.
45. **Credential-sync monitor handoff needs every foreground capture baseline.** Reusing the tmpfiles is not enough if an agent refreshes immediately on startup before `__monitor` establishes sync. Store safe SHA-256 hashes in the per-agent `creds_sync_baselines` map and pass them to the monitor so a startup rotation is detected as tmpfile → host. The singular baseline remains only as a legacy fallback.
46. **Codex host credentials follow host `CODEX_HOME`, not always `~/.codex`.** Babysit pins in-container `CODEX_HOME=/home/node/.codex`, but credential capture must resolve the host's live Codex home first. If the user runs host Codex with `CODEX_HOME=/Users/mentor/.agents/`, hardcoding `~/.codex/auth.json` copies stale auth into the container and reproduces the "refresh token was already used" failure even after the sync race fixes. Resolve host Codex auth/config from `process.env.CODEX_HOME || "~/.codex"` and only pin the container home separately.
47. **Ripgrep upstream only ships `.deb` packages for amd64.** `src/docker/assets/Dockerfile` must not derive a ripgrep `.deb` URL from `dpkg --print-architecture` (`arm64` 404s). Install `ripgrep` through Debian apt instead, or use the upstream tarball names explicitly per architecture. Regression coverage lives in `tests/docker.test.js`.
48. **Dockerfile installs must fail fast.** Do not add `|| true`, stderr redirection, or `curl | sh` without `pipefail` around tool/agent installs in `src/docker/assets/Dockerfile`. A published image missing codex/gemini/claude/opencode is worse than a failed build. Keep the final `command -v` smoke gate updated when adding required tools.
49. **Codex config.toml must not be bind-mounted as a single file.** Codex persists default-model changes by writing a temp file and renaming it over `${CODEX_HOME}/config.toml`; a single-file bind mount accepts in-place writes but rejects atomic replacement, surfacing as `Failed to save default model: failed to persist config.toml at /home/node/.codex/config.toml`. Mount a writable temp directory at `/home/node/.codex`, put the injected `config.toml` inside it, then layer narrower auth/global mounts (`auth.json`, `AGENTS.md`) afterward.
50. **macOS caffeine belongs to the monitor, not the foreground attach.** The foreground `babysit <agent>` process exits when the user detaches from tmux, while `__monitor` stays alive for the real active session. Start `caffeinate -dimsu -w <monitor-pid>` in `cmd_monitor`, not `cmd_start`, so macOS remains awake after detach and automatically drops the assertion when the monitor dies.
51. **Initial prompt belongs in `config.initial_prompt`, not agent CLI args.** Babysit now types the launch prompt into the tmux pane with `send_text` after creating the session. Fresh `babysit.yaml` files include the generated default prompt directly; `null` or `""` means "send nothing". Do not reintroduce Claude `--append-system-prompt`, Codex positional prompts, Gemini `-i`, or OpenCode `--prompt` for Babysit's built-in prompt; tests assert the Docker command does not expose it.
52. **Dockerfile tool installs need smoke-gate coverage.** When adding agent-friendly tools to `src/docker/assets/Dockerfile`, add them to the final `command -v` loop or a dedicated equivalent. Shell functions like nvm need a sourced bash smoke (`source "$NVM_DIR/nvm.sh" && command -v nvm`) because they are not standalone binaries.
53. **Do not install `just` through the base apt layer.** The Docker Image workflow failed on `node:24-slim` with apt exit 100 when `just` was included beside `shellcheck sqlite3 tree ripgrep`. Install `just` from the upstream multi-arch musl release assets and keep the final `command -v just` smoke gate.
54. **Nested Babysit with `--docker` must mount the host workspace path, not `/workspace`.** Docker-outside-of-Docker talks to the host daemon through `/var/run/docker.sock`; bind mount sources are resolved on the daemon host. Outer `--docker` sessions export `BABYSIT_HOST_WORKSPACE`, and `build_docker_command` maps `/workspace/...` back through that env var before rendering `-v <source>:/workspace`. Without this, an inner Babysit session would ask the host daemon to mount `/workspace`, which usually does not exist on the host.
55. **`--docker` pierces sandbox/mudbox expectations.** The outer container may have no workspace mount (`--sandbox`) or a read-only workspace (`--mudbox`), but Docker socket access can start sibling containers with host bind mounts. Babysit warns and requires explicit `Y` for `--docker --sandbox` / `--docker --mudbox` outside YOLO; in YOLO mode confirmations are skipped by design.
56. **Never pass Babysit metadata ids to agent-native resume.** Babysit ids look like `YYYYMMDD-HHMMSS-rand` and only identify `~/.babysit/sessions/*.json`; agents expect their own UUID/thread/session ids. If `agent_session_id` is missing, resume from the restored workspace with each agent's "latest/continue" flag (`codex resume --last`, `claude --continue`, `gemini --resume latest`, `opencode --continue`) instead of passing the Babysit id through. Also do not type `config.initial_prompt` on resume — it becomes an accidental new user message in the old conversation.
57. **Missing `config.initial_prompt` is not the same as explicit opt-out.** Older `babysit.yaml` files may lack the field entirely. Treat absence as "use the generated mode-aware launch prompt" so Codex and the other agents still receive Babysit's startup instructions. Preserve `initial_prompt: null` and `initial_prompt: ""` as explicit "send nothing" values.
58. **Multi-line tmux `send-keys -l` is not paste.** Literal newline bytes become Enter key presses for terminal TUIs. For startup prompts, this can make Codex render duplicated/garbled prompt text or submit partial messages while its full-screen UI is still initializing. Wait for Codex's first TUI screen, then use tmux `set-buffer` + `paste-buffer -pr` so bracketed paste preserves the multi-line prompt as one composer value before the final Enter.
59. **Nested Docker must host-remap every `/workspace` bind source, not only the main workspace.** Docker-outside-of-Docker resolves bind sources on the daemon host. E2E initially passed `/workspace/...` tmpfiles/config dirs/credential files through unchanged, so Docker created directories at file targets or failed before the fake agent booted. Route all bind-mount sources through `resolve_workspace_mount_source()` before rendering `-v`; set E2E `TMPDIR` under `/workspace` so credential/config tmpfiles are host-visible through `BABYSIT_HOST_WORKSPACE`.
60. **Claude startup prompts need a TUI readiness gate too.** `babysit claude --yolo` can echo the launch prompt into the pane before Claude has switched into its full-screen composer, producing duplicated prompt text before the welcome screen and again in the input area. Treat Claude like Codex: wait for the first `Claude Code v...` screen before calling `send_text`.
61. **Resume needs agent-native state, not just credentials.** Claude uses named volumes for `/home/node/.claude/{projects,plans,todos}`; Codex, Gemini, and OpenCode also need persistent transcript/session volumes. Mount those for non-sandbox runs, stage credential files into their narrower targets before start, and keep session-id capture patterns broad enough for Codex exit hints and OpenCode `ses_...` ids.
62. **Codex treats fast tmux literal typing + immediate Enter as paste burst newline.** Codex 0.130's composer has paste-burst detection: rapid `tmux send-keys -l "Keep going"` followed by `Enter` can leave the text unsubmitted and insert a newline in the input box. Use tmux `set-buffer` + `paste-buffer -pr` for automated message text, even single-line loop prompts, then send Enter as a separate key.
63. **Fake-agent E2E native ids must be globally unique.** Dockerized fake agents often run as PID 1, so PID-derived UUIDs collide across Claude/Codex/Gemini/OpenCode sessions. `load_session()` can resolve by native id, so duplicate fake native ids can make resume tests pick the wrong agent metadata.
64. **Credential setup and Docker-copy sync are cross-agent.** Foreground launches capture every supported agent's credentials so one agent can invoke the others. The detached monitor must reuse `creds_tmpfiles`, reconnect each one to the saved `container_id`, pull rotations from the stopped/running container, then remove the stopped container only after the final flush. Keep legacy `creds_tmpfile` fallback for old session records.
65. **Do not combine a staged credential with a temporary parent bind.** A `docker cp` into `/home/node/.codex/auth.json` can be hidden by a later `/home/node/.codex` bind. When any agent credential uses staged transport, convert ephemeral parent config mounts into seed copies too, upload parent config before the narrower credential, and keep persistent child session paths as named volumes.
66. **Codex's internal sandbox must be disabled in Docker even outside YOLO.** Normal `babysit codex` sessions still need approvals, but Codex's default `workspace-write` sandbox uses bubblewrap and fails inside Babysit's unprivileged Docker container with `bwrap: No permissions to create new namespace`. Use `--sandbox danger-full-access` for non-YOLO Codex Docker launches so approvals remain intact while Docker provides the isolation. Keep `--dangerously-bypass-approvals-and-sandbox` only for YOLO, where approvals should also be skipped.
67. **GitHub CLI auth is not just `~/.config/gh`.** `gh auth login` may store the token in the platform credential store instead of `hosts.yml`, so a container with only the host config dir mounted can still report "not authenticated". Babysit must use host `gh auth token` at launch and pass the result as `GH_TOKEN` / `GH_ENTERPRISE_TOKEN`, while mounting `~/.config/gh` read-only for aliases and host settings. Keep token discovery out of `build_docker_command()` so unit tests and dry renderers do not probe or print a real host token. Also, only let direct env tokens short-circuit host extraction when they match the active host class: `GH_TOKEN` for github.com / `*.ghe.com`, `GH_ENTERPRISE_TOKEN` for GHES. In nested Docker (`BABYSIT_HOST_WORKSPACE`), skip config-dir binds unless the source is under `/workspace`; otherwise the host daemon sees a container-only path such as `/home/node/.config/gh` and rejects the mount before the session starts. Token extraction/env passthrough should still run when the config bind is skipped.
68. **Boot auth checks are real Dockerized prompt calls, not credential-file probes.** `cmd_start` now sets up credential mounts first, then runs every selected agent through the Babysit Docker image with its adapter `auth_check.args(prompt)`. Tests or E2E harnesses that launch Babysit must make the fake `claude`/`codex`/`gemini`/`opencode` binaries available inside the Docker image; host PATH fakes are not sufficient for the auth check itself. The fake agent must exit 0 and print `ok` for Claude `-p`, Codex `exec`, Gemini `-p`, and OpenCode `run` shapes, otherwise startup will prompt `Unauthenticated agents: ... Exit? [Y/n]` and non-TTY tests will hang. Timeout cleanup must remove the named probe container explicitly (`docker rm -f ...`); killing the `docker run` client with SIGKILL does not propagate SIGKILL into the container.
69. **Boot auth checks are configured, not relevance-gated.** `cmd_start` checks only the agents selected in host-level `~/.babysit/config.json` (`auth_check_agents`, default `codex` + `claude`). Do not reintroduce active-agent, recent credential mtime, auth env var, or `~/.babysit/host-auth-cache.json` selection logic; users change the checked set with `babysit config`.
70. **Docker Desktop for Mac may not expose `/var/run/docker.sock`.** Newer/no-admin Docker Desktop installs can leave the privileged `/var/run/docker.sock` symlink absent while Docker still works through the user socket (`~/.docker/run/docker.sock`) or the active Docker context. `--docker` startup must call `resolve_docker_socket_path()` and pass the resolved host path into `build_docker_command()`; do not restore a raw `docker_socket_available()` preflight against the default path only. Resolver precedence should mirror Docker CLI expectations for local sockets: `DOCKER_HOST`, active context, then default/macOS fallback paths. Keep host probing out of `build_docker_command()`; command rendering should consume a supplied socket path or the literal default.
71. **A Docker binary is not enough; the daemon must answer before tmux launch.** If Docker Desktop is installed but stopped, `docker run` exits inside the detached tmux pane and `tmux attach` can show only lowercase `no sessions`. Run a `docker info`-style daemon preflight in `cmd_start` before creating tmux, and keep a short-lived pipe-pane startup diagnostic log until the agent has survived the launch window so fast container errors are printed instead of replaced by a bogus `babysit resume <id>` hint.
72. **`~/.babysitrc` must be sourced as the agent user, not root.** The file is host-local env setup and may use `$HOME`; source it from the entrypoint after uid remap via `gosu node` with `set -a`, so plain `KEY=value` assignments become environment variables for the coding agent. Also propagate `BABYSIT_HOST_BABYSITRC` when mounting it so nested Docker-outside-of-Docker runs can remount the original host path instead of the inner `/home/node/.babysitrc` bind target.
73. **Tests for direct `~/.babysitrc` mounting must clear `BABYSIT_HOST_BABYSITRC`.** Babysit sessions export the carried host rc path for nested Docker. Unit tests that assert the non-nested `babysit_rc_path` behavior need `with_env({ BABYSIT_HOST_BABYSITRC: undefined }, ...)`, otherwise running the suite from inside Babysit makes `build_docker_command` prefer the carried host path and the tests fail for the wrong reason.
74. **Numeric `babysit open` selectors are global active-list ordinals.** All-digit session names must stay reserved so `babysit open N` always selects row N from `babysit list` and never falls through to tmux fuzzy matching. A current-directory table is only a filtered view and must retain each session's global list number.
75. **Do not advertise host-native sessions as Babysit-resumable.** Host Codex/Claude transcript stores are separate from Babysit's persistent Docker volumes. A UUID discovered under host `~/.codex` or `~/.claude` may be valid for the native CLI but unavailable inside a Babysit container. Bare `babysit resume` must use `~/.babysit/sessions` as its source of truth, display the Babysit ID as the canonical selector, and show the captured native ID only as metadata. Repeated resumes retain the same native ID, so native-id lookup must prefer the newest Babysit launch record.
76. **A selector-less resume is metadata-only only when it is agent-less too.** `babysit resume` should skip Docker/tmux dependency checks and list the local registry, but `babysit claude resume` / `babysit codex resume` still dispatch to `cmd_start` and need the normal dependency preflight. Test `verb`, `agent`, and `session_id` together when classifying the listing form.
77. **Old Watchtower images do not reliably honor `enable=false`.** Current containrrr-lineage forks exclude containers carrying `com.centurylinklabs.watchtower.enable=false`, but high-pull legacy images such as `centurylink/watchtower` and Docker Hub's old `v2tec/watchtower:latest` predate reliable default exclusion. Keep Watchtower recognition repository-exact and warn for unknown or legacy names; a broad `*/watchtower` allowlist can silently expose active Babysit sessions to replacement.
78. **Tests must not write fixtures into the live session registry.** Cleanup cannot protect `~/.babysit/sessions` from interruption or identifier collisions. Inject in-memory session loaders into CLI commands instead of calling `save_session()` from unit tests.
79. **Host profile isolation must gate copies, executable setup, live attaches, and visible binds.** `--ignore-host-agents-md` cannot stop at `~/.agents`: gate native globals/skills, copied settings, `~/.babysitrc`, GitHub aliases/config, and global loop reads. A live unisolated container cannot gain this boundary, so reject a newly requested isolated attach. Build generated config, credential files, sanitized GitHub state, and secret env bootstraps into a typed `docker create` → `docker cp` launch plan; secrets must not enter `Config.Env` or bind metadata. Keep cleanup ownership through a confirmed running state, omit `--rm` for staged sessions, final-pull refreshed credentials from the stopped container, then remove it explicitly. Gemini keeps only OAuth/account selection, never policy/UI/tracking state.
80. **Auth probes can rotate OAuth credentials too.** A real prompt-level auth check is not read-only: it may exchange a refresh token. Pull only the probed agent's staged credential back before removing its auth-check container, especially because checks run concurrently and pulling every agent would reintroduce stale cross-probe races.
81. **A failed final credential pull is a recovery state, not successful cleanup.** Periodic sync failures may stay nonfatal, but `stop()` must propagate a failed Docker pull or host write. Auth probes, foreground startup/handoff failures, and signals must retain both the stopped container and private client-side sync file when the final flush fails or cannot run; deleting either can destroy the only valid rotated token. Aggregate multi-agent shutdown must await every controller before deciding recovery state.
82. **`sudo docker cp` changes local ownership.** Docker creates local pull destinations with the UID/GID of the invoking user, which is root through the sudo-routed Docker path, and agent-side rewrites may restore mode 0600. Normalize ownership even when a root-owned pull is already mode 0666: the later in-place rewrite can write it but cannot chmod it. The 0700 private parent remains the host secrecy boundary.
83. **Credential source-wins checks must span the Docker pull await.** Reading the host credential only before `docker cp` leaves a race where a host re-login during the pull is overwritten by older container state. Serialize periodic/final ticks, re-read the source after each pull, and push a changed host credential back into the container instead of writing the pulled copy to the host.
